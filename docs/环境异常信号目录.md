# 环境异常信号目录

检测对象是当前 Android 运行环境，不是本应用自己的签名、安装来源或 DEX 完整性。
用户界面只显示短句：结论、实际值、参考值、建议。原理、误报和出处留在这里以及 `rawEvidence` / `sourceAttribution`。
双层验证（源码交叉审查 + API 35 模拟器实测）见 [双层验证矩阵](双层验证矩阵.md)。

未命中不能证明环境正常。Root 或 Hook 线索也不等于恶意。看不到路径不等于没有隐藏框架。
权限被拒绝记为「无法检查」，不当成正常，也不当成命中。

筛选顺序：证据是否明确、无特权能否读到、误报是否可控。VPN、开发者选项、无障碍、外接键鼠只记录，不单独当异常。

## 未实现 / 需特权

| 项 | 原因 |
| --- | --- |
| 执行 `su` 或 `which su` | 可能弹出授权或改变系统状态，不做 |
| Play Integrity、SafetyNet | 闭源或需 Google 服务，不引入 |
| 本应用签名、安装来源、DEX 完整性、FLAG_DEBUGGABLE | 产品明确排除自保护 |
| 用户 CA 证书枚举 | `/data/misc/user/0/cacerts-added` 对普通应用通常不可读。读不到不能编造成 0 |
| KernelSU / APatch 的内核特征、Magisk deny list | 需要 root 读内核或管理器私有数据 |
| Frida 默认端口主动连接 | 会访问本地端口并拖慢扫描，且端口可改。当前只看 maps |
| 全盘搜索 su | 无权限且误报高 |

## 模拟器预期

本次 API 35 x86_64 模拟器的 `ro.build.tags` 是 `dev-keys`。shell 能读到 `ro.secure=1`、`ro.debuggable=1`，应用域 `getprop` 为空，界面写「未读到」。这只说明测试系统，不能当成「已在真机验证 Root」。

调试附加已在这台模拟器用 `am start -D` 加 `jdb` 做过正例：`rt.debug.tracer` 为「疑似调试器已附加」，`TracerPid=0`，`Java调试器=true`。断开后回到 `false`。这符合 OWASP：只调试 Java 时 TracerPid 可以仍是 0。

Frida 17.27.4 官方 `frida-server`（wxWindows Library Licence，未纳入本仓库）在 `adb root` 下附加成功，应用内脚本执行了。同时 `/proc/<pid>/maps` 没有 `frida-agent` / `frida-gadget`，线程名也没有 `gum-js-loop` 或 `gmain`。名字扫描因此未命中。这是漏报，不是「没有 Frida」。没有把没观察到的内存特征字符串加进规则。
