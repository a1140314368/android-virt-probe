# 双层验证矩阵

检测对象是应用当前看到的运行环境，不是本应用签名或 DEX 自校验。
状态只有四种：通过、不符已修、未覆盖、受限。
单元测试只证明规则，不算环境实测。没有 Magisk、KernelSU、APatch、Frida、真实容器、调试器附加时，写受限或未覆盖，不写成支持。

## 不符已修

1. `con.boot.state` 把 yellow 说成验证失败并标为高。已按 AOSP 改成「锁定但自定义信任根」，严重级别为中。空值建议写明未知，不要当成 green。
2. `rt.build.trust` 把应用读不到的 `ro.secure` / `ro.debuggable` 写成「空」，像是值就是空字符串。已改成「未读到」。`dev-keys` 仍是线索。shell 上的 `ro.debuggable=1` 应用读不到，不能填进结果。

## Frida 17 与原生调试（本轮）

Frida 17.6 起官方说明注入不再使用 ptrace，并在子进程里回滚 payload，所以 maps 和线程名可以是干净的。本机用官方 `frida-server` 17.27.4 附加后，应用内脚本已执行。root 读到的抽象套接字是 `@/frida-zymbiote-<随机后缀>`，与 [frida-core linux-host-session.vala](https://github.com/frida/frida-core/blob/17.9.7/src/linux/linux-host-session.vala) 里的 `"/frida-zymbiote-" + Uuid` 一致。应用自己读 `/proc/net/unix` 得到空或 `Permission denied`，`run-as` 也是 Permission denied。因此应用不能把这个套接字当成已检出。

规则改为：套接字表读不到或空读时，`rt.maps.inject` 是「无法检查」，不是「未看到」。这只避免把未知写成未发现。Frida 17 正例在应用侧仍然漏报，这项没有完成。

`/data/adb/magisk` 用 `adb root` 建成 755 后，`run-as` 仍是 Permission denied，目录已删除。SELinux 不让应用看见该路径。

NDK `lldb-server gdbserver --attach` 曾把目标进程的 `TracerPid` 设成非 0，`killall` 后又回到 0。发行版 `lldb-18` 能连上并看到 `SIGSTOP`，`continue` 后进程以 `lost connection` 退出。Ubuntu `gdb` 15 不认识 stub 的 `x86_64` 描述。应用内的 continue-scan 还没闭环。细节在 `docs/测试环境边界.md`。Java 调试正例仍以上一轮 `jdb` 为准。
