# 输入来源对照

这是观测，不是真人认证。`isVirtual=false` 不能证明是真人。系统软键盘的虚拟设备也不能判作弊。遮挡标志不是注入。压力、面积、时长相同只记弱观察，不设统一阈值，也不打真实性分数。设备没有的轴写成不可用。

依据：

- Android `InputDevice.isVirtual()`：虚拟设备，例子是虚拟键盘。
- Android `MotionEvent`：`FLAG_WINDOW_IS_OBSCURED=0x1` 是触摸穿过遮挡，`FLAG_WINDOW_IS_PARTIALLY_OBSCURED=0x2` 是触摸点以外还有遮挡。
- AOSP `MotionEvent.FLAG_IS_ACCESSIBILITY_EVENT` 注释写明值为 `0x800`，当前主线仍是 `@hide @TestApi`。CTS `AccessibilityGestureDispatchTest` 断言无障碍 `dispatchGesture` 的 `deviceId` 是 `VIRTUAL_KEYBOARD`，并且带这个标志。`MotionEventInjector` 把工具类型设成 `TOOL_TYPE_UNKNOWN`，来源是触屏。

## API 35 模拟器实测

镜像是 `google_apis` x86_64，`userdebug`。模拟器没有物理手指，下面的「控制台触屏」只是模拟器自己的 virtio 触屏，不能当真人基线。

| 方式 | 实际事件 | 结论 |
| --- | --- | --- |
| 控制台 `event mouse` 触屏点击、长按、滑动 | 设备 `virtio_input_multi_touch_1`，`isVirtual=false`，来源触屏，工具手指，`flags=0`。压力轴可用，但压力停在 1.0。 | 证据不足。设备名像模拟器，不写成注入，也不写成真人。 |
| `adb shell input tap` / 同点滑动 800ms / 短滑动 | `deviceId=-1`，设备名 `Virtual`，`isVirtual=true`，来源触屏，工具手指，`flags=0`。压力轴不可用。单击的按下和抬起时刻相同，只作弱观察。 | 发现输入异常线索：触屏事件使用了虚拟键盘设备号。 |
| `adb shell input text a` | 设备 `-1`，来源键盘，`isVirtual=true`。不记录按键码。 | 本次未发现。和系统软键盘同一类虚拟设备，不能判作弊，也分不出这是 shell 注入。 |
| 本应用无障碍服务 `dispatchGesture` 单击 | `flags=0x800`，工具 `UNKNOWN`，设备 `Virtual`，`deviceId=-1`，来源触屏，压力 1.0，时长 60 毫秒，1 指。 | 发现输入异常线索：这次事件带无障碍生成标志。 |
| 无障碍双指按钮 | 这次只记到按下按钮时的 `adb` 点击，没有收到 `pointerCount=2` 且带 `0x800` 的事件。 | 双指注入这次没有落地，不能写成已经测到。 |

点测试输入框后，这台镜像的 Gboard 打开的是手写笔面板，不是字母键盘，所以没有单独的字母键事件。软键盘结论以上面的 `input text` 为准：虚拟键盘设备本身不是作弊结论。

## 真机最短步骤

1. 安装 `sample-app-input-debug.apk`，打开「输入体验」。
2. 用手指完成点一下、按住约半秒、滑动、双指。看每格结果。`isVirtual=false` 只说明系统没把设备标成虚拟设备。
3. 在「测试输入，不要填密码」里用系统软键盘打一个普通字母。预期是「本次未发现」，并说明不能判作弊。
4. 需要对照时，只在系统设置里打开本应用的「输入来源测试」，回到页面点「无障碍测试点击」，看是否出现无障碍生成标志。测完关掉这项服务。
5. 技术详情里核对来源、工具、flags 和设备名。不要输入密码，也不必上传。
